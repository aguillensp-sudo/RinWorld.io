## Síntoma

**El push del cierre del Día 16 no disparó CI porque su propio mensaje nombraba el marcador de salto.** El cuerpo de `7eeb6d8` decía, literal, que era el primer commit del arco SIN el marcador, y lo escribía entre corchetes: GitHub busca el marcador en el mensaje ENTERO del commit de cabeza de un push, no solo en el título. **Se diagnosticó primero como otra cosa, y se dejó escrito como bloqueo 🔴 del PO:** el token de `git push` en Windows Credential Manager, con `gh auth setup-git` como arreglo propuesto. Falso, y comprobable sin tocar credenciales: la API de actividad del repo (`/activity?ref=refs/heads/mvp/bootstrap`) muestra el push `c6cab7e→7eeb6d8` hecho por el mismo actor que ya había disparado CI el 13-sep (`bab1689`, run `34746060926`), y los seis push intermedios llevaban el marcador en el título a propósito. «Cero corridas desde el 16-sep» no era síntoma de nada: en esos días no hubo ningún push sin marcador salvo ese. La descarta de «no lleva el marcador» se hizo mirando el título

## Acción en V1

**Un mensaje de commit no escribe el marcador literal, ni siquiera para decir que no lo lleva:** se nombra como «el marcador de salto de CI». Y un «descartado» se comprueba contra lo que la plataforma lee —aquí, el mensaje completo—, no contra lo que se ve en `git log --oneline`. Confirmado con el push de `5cfbf2f`, sin marcador en ninguna parte del mensaje y con las mismas credenciales de siempre: creó el run `35200727115`
