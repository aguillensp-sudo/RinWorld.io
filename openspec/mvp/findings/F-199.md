# F-199

- **Fecha:** 2026-09-24
- **Origen:** `VisibilityScroll.test.ts` (INV-07) fallaba con `expected '' to match /overflow-y:\s*auto/` aunque el CSS del Coder llevaba la regla; una regex volcada a pantalla salía sin ninguna barra
- **Clasificación:** `HARNESS`
- **Capability:** —

## Síntoma

**El shell de la herramienta de comandos se come una capa de barras invertidas dentro de un heredoc, incluso entrecomillado (`<<'EOF'`).** `(?:^|\\})\\s*\\.${selector}` llegó al fichero como `(?:^|\})\s*\.${selector}`, una regex que nunca puede casar: **el test de scroll de `INV-07` y el de `SRCH-02` no podían pasar nunca**, y la corrida 01 de `INV-07` escaló por eso (y por `F-200`). No habría dado ninguna señal más que un rojo con el artefacto correcto. Los que se crearon con el editor de ficheros (`Write`/`Edit`) salieron bien (`SRCH-03`)

## Acción en V1

Los dos tests reescritos con `Edit`; comprobado que el artefacto de `INV-07` pasa las 40 pruebas con el contrato corregido. **Regla nueva para quien escriba contratos: todo fichero con barras invertidas (regex, escapes) se crea con el editor de ficheros, nunca con heredoc.** Anotada en §8 de `ESTADO-V1.md`
