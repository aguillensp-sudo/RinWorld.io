# F-212

- **Fecha:** 2026-09-25
- **Origen:** Al diseñar `0037` para INVT-01
- **Clasificación:** `SPEC`
- **Capability:** organization-onboarding

## Síntoma

**La spec y el HTML aprobado prometen un correo que el proyecto no puede enviar.** *«El sistema envía el email de invitación con token válido por 7 días»* (`additional-user-invitation`) y el HTML: *«Invitación enviada. El usuario recibirá un email con el enlace de registro»*. No hay proveedor de correo en el proyecto y el flujo de registro por invitación (Ruta 00.1, `FRU`/`REG-01`) no existe: no hay nada que canjee un token

## Acción en V1

`0037` REGISTRA la invitación (Pendiente, 7 días) y la pantalla dice *«Invitación registrada. El envío del correo de invitación llega con el flujo de registro por invitación.»*: nunca afirma un correo. Mismo criterio que `ADMIN-01` (`DECISIONES-V1.md`). Sin columna de token: cuando exista el flujo, colgará de estas filas

## Estado

**ABIERTO — del PO.** Hasta que exista el flujo (correo + `FRU`), una invitación registrada no lleva a nadie a ningún sitio: es un cupo reservado, no una invitación entregada
